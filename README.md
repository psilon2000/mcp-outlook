# mcp-outlook

Два локальных MCP-исполнителя для корпоративного Exchange. mcp-outlook-ews использует EWS с NTLM для ограниченного чтения почты/календарей и подготовки встреч. mcp-outlook — отдельный браузерный исполнитель для действий, специфичных для интерфейса OWA; без проверенной карты UI он отказывает. Данные писем и календарей не записываются в файлы.

## EWS: основной канал

EWS на https://web.modulbank.ru/EWS/Exchange.asmx проверен с разрешённой учётной записью: авторизация NTLM, чтение метаданных inbox и calendar и адресное чтение одного письма работают. Окружение Python: `python3 -m venv <отдельный-каталог>`, затем `<отдельный-каталог>/bin/python -m pip install -r requirements-ews.txt`; запуск: `<отдельный-каталог>/bin/python src/ews_server.py`. Протокол сервера — stdio MCP; профиль OpenCode в dp подключает его отдельно от браузерного инструмента.

Укажи только путь к закрытому локальному файлу через `OWA_EWS_CREDENTIAL_FILE`: первая строка — логин DOMAIN\user, вторая — пароль. Файл не хранить в Git и не передавать модели. EWS использует системное хранилище сертификатов Linux; для текущей системы путь к нему — /etc/ssl/certs/ca-certificates.crt. Если поиск ящика по логину даёт несколько результатов, можно локально задать точный SMTP-адрес через `OWA_EWS_MAILBOX`; сервер проверит его присутствие среди результатов AD. Для чтения тела выбранного письма нужен флаг `OWA_EWS_ALLOW_MAIL_BODY=true`, для деталей события — `OWA_EWS_ALLOW_CALENDAR_DETAILS=true`, для разрешённых чужих календарей — `OWA_EWS_ALLOW_SHARED=true`; создание события дополнительно требует `OWA_EWS_ALLOW_WRITE=true` и личного нажатия в локальном прокручиваемом окне подтверждения (Tkinter). Отсутствие GUI = отказ в записи.

`ews_add_shared_calendar` только проверяет доступ к календарю по заданному адресу. Он не регистрирует его в списке MCP и не создаёт закладку в OWA: ews_calendar_events и без этого шага принимает явно названного владельца. Обычный инструмент браузерного MCP add_calendar в этой установке не откалиброван для цепочки «Из каталога» и отказывает; постоянное добавление делает только ограниченный калибратор ниже. Ответ `submitted_verify_in_owa` при создании встречи означает попытку сохранения и рассылки, а не доказательство доставки приглашений; `core_fields_verified` относится только к повторному чтению базовых полей. Ответ `event_result_uncertain` означает, что Exchange мог сохранить событие несмотря на ошибку сети: не повторяй CreateItem до ручной сверки на дубликат.

Если делегированной папки чужого календаря нет, EWS использует GetUserAvailability: при правах Free/Busy возвращает только интервалы занятости, без тем, описаний и участников. Если Exchange разрешает Detailed, можно получить лишь разрешённые тему и место неперсонального события; приватные события остаются без деталей. Открытие чужого календаря в OWA не выдаёт новых прав.

Для постоянного добавления календаря в интерфейс OWA после подтверждения конкретного адреса используется отдельный ограниченный запуск калибратора с `OWA_CALIBRATE_ACTION=add_calendar`, `OWA_CALIBRATE_TARGET_EMAIL=<адрес>`, `OWA_CALIBRATE_TARGET_SURNAME=<фамилия>`, `OWA_CALIBRATE_SELECT_RESULT=true`, `OWA_CALIBRATE_OPEN_SELECTED=true` и путём к закрытому файлу в `OWA_CREDENTIAL_FILE`. Он проверяет, что календарь не присутствует в видимом списке, находит точный адрес в каталоге и **ещё раз** спрашивает владельца в отдельном локальном окне перед единственным нажатием «Открыть». После неопределённого ответа проверяй видимый список через новый вход с `OWA_CALIBRATE_ACTION=check_calendar_sidebar` и фамилией; не запускай добавление повторно вслепую. Скрипт не предназначен для произвольного браузерного доступа и не выводит содержимое писем/встреч.

Если вместо адреса указано `OWA_CALIBRATE_SELF_SEARCH=true`, для поиска своего SMTP-адреса калибратору дополнительно нужен `OWA_EWS_PYTHON` — путь к Python с установленными requirements-ews.txt. Этот режим только для исследования UI, при добавлении чужого календаря указывай точный адрес напрямую.

## Запуск

Требуются Node.js 20+, графическая сессия и доступ к https://web.modulbank.ru/owa/. Установить зависимости: `npm ci`, затем браузер: `npx playwright install chromium`. Проверить `npm test` (перед тестами собирается актуальный dist); после сборки запустить `npm start` или подключить отдельным профилем OpenCode из dp. Базовый профиль dp сервер не включает. Для тестов рабочая учётная запись не нужна.

Перед каждым запуском браузера сервер проверяет сертификат web.modulbank.ru и имя узла через системный CA bundle Linux, затем закрепляет только проверенный открытый ключ сертификата для этого процесса Chromium. Это нужно потому, что изолированное хранилище Chromium не включает установленный в ОС российский УЦ. При неуспехе системной проверки браузер не открывается; глобальная настройка игнорирования TLS-ошибок не используется.

`start_session` открывает страницу входа в видимом браузере **только при наличии проверенной карты интерфейса**. Логин, пароль и MFA пользователь вводит сам; агент никогда их не получает. Пока вход не подтверждён, остальные операции возвращают отказ. `close_session` закрывает контекст; автоматического повторного входа нет.

Для первичного обследования без карты UI: `npm run calibrate`. Команда открывает отдельное окно входа, ждёт до 180 секунд (предел можно увеличить переменной `OWA_CALIBRATION_WAIT_SECONDS` до 1800), после ручного входа выводит только ограниченный список структурных признаков элементов календаря и пустого редактора события. Значения полей, письма, события, снимки экрана и cookies не выводятся и не сохраняются. Это не включает рабочие операции MCP автоматически: селекторы и настройки доступа всё равно нужно проверить для фактической версии OWA.

Для однократного входа без ручного ввода можно передать **только путь** к локальному файлу через `OWA_CREDENTIAL_FILE`. В файле первая строка — логин вида DOMAIN\user, вторая — пароль; содержимое читается внутри процесса, не выводится и не включается в командную строку. Калибратор отправляет форму один раз; при отказе не повторяет попытку. Файл с секретом хранить вне репозитория и не добавлять в артефакты проверки.

## Настройка доступа

Оператор указывает переменную `OWA_UI_MAP_FILE` с путём к локальной JSON-карте именно проверенного интерфейса. Поля схемы — в `src/ui.ts`. Карта не передаётся как аргумент MCP. Для незнакомого интерфейса не создавай карту по догадке: если параметр отсутствует, инструменты чтения и записи откажут до обследования OWA после безопасного входа владельца. `appReady` — уникальный признак авторизованной страницы; `mail.safeToList` и `mail.safeToOpen` разрешено выставлять в true лишь после проверки побочных эффектов области чтения и уведомлений. Карта описывает устойчивые селекторы, `calendar.timeZone` — фактический часовой пояс отображения. Значения повторений `frequencyValues`, `endValues` и `ordinalValues` берутся из реального редактора, не из предположений о Exchange.

Номера `recurrence.weekdays` — ISO 8601: 1 = понедельник, 2 = вторник, …, 7 = воскресенье. Ключи `editor.recurrenceWeekdays` в карте UI обозначают именно эти дни **независимо от порядка отображения в OWA**. В окне подтверждения исполнитель также показывает названия выбранных дней.

Второй рубеж — локальные переключатели, по умолчанию выключены: `OWA_ALLOW_MAIL_METADATA`, `OWA_ALLOW_MAIL_BODY`, `OWA_ALLOW_CALENDAR_METADATA`, `OWA_ALLOW_CALENDAR_DETAILS`, `OWA_ALLOW_SHARED_CALENDARS`, `OWA_ALLOW_EVENT_WRITE`. Значение `true` разрешено устанавливать лишь для проверенной категории данных и согласованного применения модели. OpenCode не должен управлять настройками. Запись требует ещё и локального диалога: до сохранения пользователь видит заполненные поля и распознанных адресатов и нажимает «Подтвердить один раз». Без графической среды запись недоступна.

Приглашение может отправить письмо участникам. Ответ `submitted_verify_fields_in_owa` означает лишь однократную отправку формы; перед объявлением результата проверь событие и доставку в разрешённой среде. При таймауте или неопределённом результате нельзя повторно нажимать «Сохранить» без сверки на дубликат.

## Ограничение

OWA за формой входа не обследован. Имена элементов интерфейса, формы повторения, права и эффект области чтения необходимо подтвердить в разрешённой учётной записи до использования на рабочей почте. Непроверенная операция останавливается с объяснением, а не выбирает «похожий» элемент или повторно отправляет приглашение. Добавление календаря и сохранение события требуют локального подтверждения с показом фактически заполненных полей. Почта может помечаться прочитанной уже при открытии папки; операция чтения отключена до отдельной проверки этого эффекта.

Исходное задание и критерии приёмки: план «Навык чтения почты и управления календарями OWA» в рабочем индексе dp от 25.09.2026.
